# 用户调研 Agent（Dify + 记忆服务 + Milvus）

帮副业者找到"真实存在、有人愿意付费"的需求：**生成访谈提纲 → 你去访谈 → 上传材料 → 提炼洞察 + 长期记忆 + 机会评分 + 可执行计划**。

## 在线演示

两个应用部署在 Dify 官方云，记忆服务 + Milvus 跑在家里的 Mac mini 上，经 Cloudflare Tunnel 以 `https://urm.wyphub.com` 对外（带令牌鉴权），见 [`deploy/macmini/`](deploy/macmini/README.md)。
云版 DSL：`python dify-apps/build_dsl.py --memory-url https://urm.wyphub.com` → `dify-apps/dist/cloud/`。

## 组成

| 目录 | 是什么 | 怎么验证 |
|---|---|---|
| `dify/docker/` | Dify 1.18 部署（上游浅克隆，**不进本仓库**；本地改动存于 `deploy/dify/`，见下） | 容器健康检查 |
| `memory-service/` | FastAPI：脱敏、多模态转文字、记忆去重/计数/检索 | `uv run pytest`（媒体测试在容器内跑） |
| `dify-apps/` | 两个 Dify 应用：提示词、代码节点、DSL 生成器 | `pytest tests`；`python build_dsl.py` 生成 `dist/*.yml` |
| `eval/` | 埋点评测集 + 端到端评测脚本 | `python run_eval.py` |

### 重建 Dify

```bash
git clone --depth 1 --branch 1.18.0 https://github.com/langgenius/dify.git
cp -r deploy/dify/docker-compose.override.yaml deploy/dify/milvus-embed dify/docker/
cp dify/docker/.env.example dify/docker/.env   # 再把 deploy/dify/env.local.example 的内容追加进去并填 <...>
```

## 两个应用

| 应用 | 输入 | 输出 |
|---|---|---|
| ① 访谈提纲生成 | 调研方向、目标用户、假设 | 按 Mom Test 的提纲；已被多人提到的痛点转为"验证付费"，未覆盖的做探索 |
| ② 访谈分析与计划 | 受访者编号、文字记录、文件（文档/图片/音频/视频） | Markdown 报告 + `plan_json`（给工作 Agent：机会评分、假设状态、带依赖的行动项） |

**同一个调研方向，两个应用的「调研方向」要填一样**，记忆按它隔离。

## 关键设计

| 问题 | 做法 | 依据 |
|---|---|---|
| 重复内容要不要存 | 同一材料→跳过；不同人说同一件事→**不新建，提及人数 +1**；同一人重复→不计数 | 重复是需求频率信号，不是噪音 |
| 怎么判断"同一件事" | 相似度 ≥0.90 直接合并；0.55~0.90 交 LLM 裁判；<0.55 新建 | 真实向量下同义(0.63~0.92)与相近不同(0.70~0.84)区间重叠，单阈值必错；25 对校准样例两段式 3 轮 0 错 |
| 防编造 | 每条洞察必须附原话，代码逐字核对（容忍 ASR 个别错字、省略号拼接需每段都存在），不过关不入库 | 不靠模型自觉 |
| 隐私 | 入库前正则脱敏（手机/身份证/银行卡/邮箱/微信/QQ）+ 显式人名替换 | |
| 长录音 | ffmpeg 切 4 分钟段并行转写（qwen3-asr-flash 单次 ≤5 分钟） | |

## 模型

| 环节 | 模型 |
|---|---|
| 提纲、洞察提取 | deepseek-v4-flash |
| 综合分析与计划 | deepseek-v4-pro（思考模式） |
| 向量 / 去重裁判 | text-embedding-v4 / qwen-plus |
| 语音 / 图像 | qwen3-asr-flash / qwen3-vl-plus |

## 评测结果（`eval/results/20261028-152158`，第 3 轮）

评测集：9 份访谈（文字 7、音频 1、截图+视频 1）+ 1 份重复提交，埋 5 个痛点、5 个陷阱。

| 指标 | 结果 |
|---|---|
| 运行成功 | 10/10（单次 93~181s，重复提交 1s 跳过） |
| 痛点提取召回 | 9/9 次运行 100% |
| 原话真实性（独立复核） | 文字类 7/7 次 100% |
| 痛点计数（主记录受访者 = 埋点受访者） | **5/5** |
| 陷阱：引导性提问 / 脱敏 / 重复提交 / 同一人回访 / 正反付费意愿 | 5/5 通过 |
| 计划 JSON 合法（字段齐全、依赖有效） | 9/9 |

三轮迭代修掉的问题：

| 轮次 | 发现 | 修复 |
|---|---|---|
| 1 | 同一痛点不同场景（相似度 0.63）没进裁判，P2 少计 1 人 | 裁判下限 0.70 → 0.55，校准集 25 对 3 轮 0 错 |
| 2 | "土办法"被裁判并进"痛点"，P3 混入无关受访者 | 只在同组类型间找合并候选 |
| 冒烟 | pymilvus 惰性 JSON + 排序导致摘要与原话错位 | 结果立即物化为 dict，加回归测试（旧代码下必挂） |

## 已知限制

- 语音转写不区分说话人；访谈者与受访者混在一起，靠提取提示词区分。
- 综合分析用思考模式，单次约 1~3 分钟。
- 生成的文字由 LLM 归纳，偶有小误（评测中提纲把 2 人提到的"差评"说成 1 人）；准确计数以记忆服务 `/v1/overview` 为准。
- 评测集是合成数据（埋点明确），真实访谈更含糊，指标会低于评测值，建议积累 10 份真实访谈后人工抽查。
- Dify 的 SSRF 代理放行了宿主机 IP，HTTP 节点可访问宿主机所有端口（仅本机自用）。
